# Medición

El contador predeterminado del runtime mide bytes UTF-8 exactos para un perfil byte a byte artificial; **no es un tokenizador de GPT, Claude ni otro LLM**. El MCP ofrece opcionalmente conteo exacto de texto mediante Python `tiktoken` para `cl100k_base` y `o200k_base`; no equivale a solicitudes completas ni a consumo reportado. El estimador `ceil(bytes/4)` está etiquetado como estimación. `hybrid` acepta una candidata formal sólo si conserva VSR en round-trip y `(candidato + glosario completo) < original` bajo el mismo contador. Un fallback no paga el glosario descartado. C1 se considera únicamente con `compactNegotiated: true` proporcionado por el llamador; el MCP en Hybrid no declara esa negociación. `observe` mantiene original. El benchmark de recuperación selectiva mide una tarea exacta y compara con búsqueda convencional; la ventaja frente a reenviar todo el documento no es exclusiva de VELIQ. No hay contabilidad de tokens de salida, llamadas de traducción LLM, reintentos ni precios de proveedor: no se informa ahorro monetario. Comparación con resumen convencional y pruebas de comprensión pendientes. Ver `docs/BENCHMARKS.md`.

C2 y C3 exigen respectivamente `c2Negotiated` y `c3Negotiated`; el MCP los acepta como declaraciones explícitas del cliente. `setupPaid` omite el glosario únicamente en perfiles declarados compatibles: no acredita comprensión ni uso previo real. C3 usa ligaduras locales y aridad, preservando el mismo AST. El benchmark mixto compara también un baseline natural fuerte con encabezados de ID y valida su VSR, no sólo frases deliberadamente verbosas. Con el glosario en cada llamada se usa fallback y no se obtiene ventaja en el corpus actual.

Instalar un observador activa recopilación automática de **bytes**, no ahorro ni tokens del proveedor. No se devuelve texto a stdout, ni se agrega glosario al contexto, ni se reemplazan mensajes. El objetivo diario requiere evaluar solicitudes completas baseline/candidata con veredictos funcionales, reintentos y recuperación incluidos antes de permitir transformaciones. Hooks que sólo agregan contexto no son un compresor transparente: pueden aumentar el costo. La compresión de espacios/JSON, el filtrado de logs y la recuperación son estrategias complementarias futuras, no resultados atribuibles al idioma.
