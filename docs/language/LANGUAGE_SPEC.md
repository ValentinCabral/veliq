# VELIQ Language 0.1

Sintaxis ASCII de términos composicionales con raíces versionadas e ID conceptual estable. Una expresión es `raiz(argumento,...)`; cada argumento es otro término o una cadena JSON. No hay operadores implícitos. `nu(x)` niega exactamente `x`; `pro(x)` prohíbe `x`, diferente de ausencia de evidencia. `seq(a,b)` ordena; `par(a,b)` expresa concurrencia. `ri("id")` identifica contenido compartido, cuya resolución es responsabilidad del receptor. `opq("...")` conserva datos exactos.

Ejemplo: `seq(sen(ri("error:1")),nar(ri("error:1")),sel(ri("tests:1")))`.

El perfil compacto experimental C1 tiene parser y serializador propios. Por ejemplo, `sen@error:1;pro{del@archivos:originales}` equivale al AST formal `seq(sen(ri("error:1")),pro(del(ri("archivos:originales"))))`. `;` expresa secuencia; `{}` determina el alcance de una obligación, prohibición, permiso, hipótesis o negación. `@` introduce una referencia ASCII exacta. Las referencias con espacios, comillas u otros caracteres quedan fuera de C1 y deben usar el perfil formal. C1 no cambia el significado de las raíces ni se negocia automáticamente con receptores.

El perfil experimental C2 conserva los mismos IDs y añade relaciones binarias explícitas y transferencia con destino: `dar@result:1>^agent-2`, `pre{mak@artifact:1}{sen@error:1}`, `kon{@condition:1}{sel@result:1}`. No permite transferir sin destino, ni omitir el alcance de `pro{...}`. Hay parser, serializador y pruebas de round-trip. No es una prueba de que un LLM entienda estas construcciones: el glosario y su costo se contabilizan por separado y C2 no se aplica automáticamente en un harness.

## C3: referentes ligados, no un diccionario de abreviaturas

C3 conserva el vocabulario y los IDs de VSR. Introduce una regla composicional: el primer token liga un sufijo de referencia dentro de esa oración. `case-001 sen error nar error sel tests` representa analizar `error:case-001`, corregir el mismo error y verificar `tests:case-001`, en ese orden. `@archivos:originales` es una referencia absoluta que nunca adopta el sufijo. El destinatario de `dar` es siempre el ID exacto de un agente, no un referente ligado.

Cada raíz consume una aridad explícita: acciones una referencia; `pro/obl/per/hyp/nu` una cláusula; `pre/pos/kon/kal/par` dos cláusulas. Una secuencia anidada usa `seq N` seguido de exactamente N cláusulas. Por ejemplo, `x pro seq 2 del file sav memory dar result agent-2` prohíbe la **secuencia completa** y luego transfiere `result:x` a `agent-2`; no equivale a prohibir únicamente la eliminación. Las cláusulas superiores se ordenan de izquierda a derecha. No hay ligaduras persistentes entre mensajes, IDs descartados ni contexto supuesto.

El parser rechaza ambigüedades, formas no canónicas, aridades incompletas, IDs fuera de ASCII y anidamiento excesivo. Para datos opacos o expresiones no soportadas se conserva el perfil formal/original. 1.000 expresiones estructurales generadas con semilla fija pasan round-trip por hash semántico, además de las pruebas de negación, destinos y CLI/MCP. Esto verifica el codec, **no la comprensión de un modelo**.

La selección de C3 en Hybrid requiere `c3Negotiated=true` declarado por el llamador. El glosario completo se cobra, salvo `setupPaid=true` explícito. Esa opción es una declaración, no una negociación ni un pago demostrado por VELIQ. El costo de un glosario retenido en el historial puede cobrarse en **cada solicitud** del proveedor; los benchmarks de texto compartido no representan esa facturación. C3 no se activa automáticamente en mensajes operativos de harnesses.

El diccionario está en `packages/language/dictionary.ts`. Tipos de raíz y aridad se validan; aún no existe una semántica universal para conceptos arbitrarios ni traducción libre. Los nuevos términos requieren propuesta versionada y pruebas de colisión, frecuencia, tokenización y comprensión. No se modifica ningún ID publicado. La traducción natural soporta ocho familias controladas en `es/en` (incluidas variantes concisas y encabezados `ID "...": ...`) y una familia en `pt/fr/de/it/nl/zh/ja/ko`. Cada texto se valida por idioma declarado y se conserva el original verificable en VSR. Fuera de las formas documentadas en `packages/semantic/vsr.ts` falla explícitamente.
