# Memoria local 0.1

SQLite WAL contiene contenido por SHA-256, registros por ámbito compuesto, versiones append-only e invalidación con versión previa obligatoria. `retrieve` busca determinísticamente ID o texto en el ámbito exacto; `getContent` recalcula hash. La memoria no resume ni embebe. El almacenamiento no cifra. Las referencias entre peers se recuperan desde el remitente explícito y se verifican por contenido. Falta política de expiración, borrado físico y ámbitos compartidos autorizados.

El perfil de documento exacto 0.1 requiere `{version:"0.1",constraints:string[],records:{id,body}[]}`. Prohíbe IDs duplicados y campos desconocidos. `storeExactDocument` guarda el documento versionado en el ámbito explícito; `selectExactRecord` exige el mismo ámbito y un ID existente, verifica el hash original, y devuelve registro, restricciones globales, versión y hashes. `selectModelContext` entrega solamente el ID, cuerpo y todas las restricciones, evitando repetir los demás registros o metadatos de auditoría. Ninguna selección convierte el texto del registro en una instrucción privilegiada. La reducción medida se limita a consultas exactas por ID sobre un documento previamente almacenado; consultas semánticas, preguntas sobre varios registros o necesidad del documento completo requieren otro mecanismo.

## Context snapshots alpha.7

`packages/memory/context.ts` publica esquemas Zod para registros con id/kind/authority/body/constraints/tags/pinned/provenance/acquiredAt/expiresAt/vsr y snapshots por ámbito/revisión/digest. VSR debe corresponder al cuerpo exacto y autoridad. Selección conserva todas las instrucciones/constraints, señala vencimiento y falla si no caben. FULL hasta ACK de snapshot histórico; DELTA con upserts/eliminaciones sólo si menor, apply verifica base/ámbito/orden/hash y detecta duplicados. ACK no presupone memoria del LLM. Integridad sin autenticación remota. CLI y MCP en [NATIVE.md](NATIVE.md). No se resume ni se cifra.
